# Feedback Desk · AI 用户反馈分析台

[English README](README.en.md)

Feedback Desk 帮助产品经理和产品运营从一批公开反馈中确认本周值得跟进的问题。审核人可以检查模型建议、点回原始 Issue、修改主题和优先级，再导出带证据的产品周报。

## 三分钟体验

项目使用蓝灰界面，由静态网站和可选的分析脚本组成。本地预览只需 Python 3，也可以使用任意静态 HTTP 服务托管 `dist/`。

```bash
python3 -m http.server 4173 --directory dist
```

打开 [http://localhost:4173](http://localhost:4173)。右上角可在中文和英文之间切换，语言偏好会保存在当前浏览器。演示主题和周报支持两种语言。Issue 引文及导入的分析文本保留原文。你也可以在主题编辑页为两种语言分别填写标题、概述和建议动作。

1. **收集反馈。** 通过「导入反馈」上传 CSV 或 JSON，先核对文件和记录预览。CSV 要有 `id` 和 `title` 两列，可选填 `excerpt`、`date`、`url`、`area`、`likes` 和 `comments`。界面提供 CSV 模板及工作区备份。追加导入会跳过重复项和冲突编号，保留当前审核与跟进记录。
2. **审核分流。** 按待审核、已确认、已搁置、已完成切换队列，也可按模块和优先级筛选。打开主题核对原文，编辑负责人、日期和备注后作出决定。修改主题文案或归并关系会把它送回待审核。
3. **生成周报。** 自动按优先级和反馈量收录 3、5 或 10 个已确认主题，也可手动勾选。导出 Markdown 会保留负责人、跟进日和原帖链接，完整审核队列可导出 CSV。演示快照内置两个已确认主题。
4. **跟进与结案。** 总览列出已逾期和未来 7 天即将到期的主题。结案后仍可在「已完成」队列查看记录，主题会从当前周报移出。

用模型分析新反馈时，可以从「导入反馈」导出原始反馈 JSON。分析返回后，若反馈集合与当前工作区一致，选择「应用分析并保留审核」即可沿用成员相同的主题记录，新分组回到待审核。浏览器工作区最多容纳 500 条反馈。分析脚本每次接受最多 100 条。

## 产品设计

- **输入**使用 62 条 Microsoft PowerToys 公开 GitHub Issues。快照覆盖 2026 年 11 月 3–26 日。样本有意覆盖重复现象和同功能近似但不同的问题。每条只保留标题、短摘录、日期、组件和原帖链接。组件字段经过参考标注。
- **归并**使用 MiniLM 对标题和摘录生成向量，在同一组件内提出相似候选。演示主题由参考标注初始化，MiniLM 负责提供候选和真实相似度。相似度衡量文本接近程度，可在审核页保留为不同主题。
- **决策**把反馈量与影响程度分开。P1 用于核心功能不可用、明显阻断或严重损失风险，P2 用于局部影响，P3 用于低影响或信息不足。审核人能编辑、拆分、合并及确认。周报按自选条数收录已确认主题，保留原帖链接。

[公开 Issue 来源](https://github.com/microsoft/PowerToys/issues)

## 人工纠偏样本与优先级推荐

在审核队列里选择「AI 建议优先级」，可以按 0–100 分的热度评分排序。评分卡展示频次（50 分，5 条封顶）、原帖互动（30 分，按 `likes + 0.5 × comments` 做对数归一化，在 20 个加权互动封顶），以及近期程度（20 分，以工作区最新 Issue 日期为参考，14 天减半）。演示数据的点赞数和评论数来自采集快照，点赞采用 GitHub `+1` 表情计数。计数缺失按 0 处理，分数不会自动修改人工优先级。

手动合并会把两个主题之间的反馈对记为 `merge / human_override`。拆开模型归并过的反馈，或直接驳回某条 AI 合并候选，会为相应反馈对记录 `split / false_merge`。普通手动拆分记录为 `split / human_override`。模型评估页可以下载 JSONL，每对 Issue 导出最后一次人工判断，例如：

```json
{"issue_a":"51906","issue_b":"51908","label":"merge","reason":"human_override","action":"manual_merge","reviewed_at":"2026-11-26T08:00:00.000Z"}
```

纠偏记录随工作区备份保存。需要训练文本时，可以使用 Issue ID 关联「导出原始反馈 JSON」的内容。人工纠偏样本单独导出，现有公开测试集指标保持可复现。

## 实测结果

将 62 条反馈按问题主题分为 18 条开发集和 44 条测试集。在开发集选择阈值，再在同一功能模块内的测试对上评估。110 对测试样本中，22 对属于同一问题。

| 方法 | 精确率 | 召回率 | F1 | 平均精确率 |
| --- | ---: | ---: | ---: | ---: |
| 字符 n-gram TF-IDF | 24.6% | 68.2% | 36.1% | 36.9% |
| MiniLM | 27.6% | 72.7% | 40.0% | 52.8% |

MiniLM 的平均精确率高 15.9 个百分点。在所选阈值下，它仍误报了 42 对，所以产品把相似对送进人工审核，并把确认设为进入周报的条件。跨语言漏合并说明当前匹配模型的覆盖范围有限。评估页还可以在 0.40–0.95 之间查看 MiniLM 的聚类阈值结果，默认对比 0.65、0.75 和 0.85。

复现评估需在本机安装 Python 依赖，运行时首次下载约 22 MB 的模型。固定版本和完整指标见代码和评估报告。

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python scripts/benchmark.py
```

[评估说明与错例](docs/evaluation.md)

## 运行生成式 AI 分析

需要 Node.js 20+ 和可调用 OpenAI Responses API 的 `OPENAI_API_KEY` 环境变量。默认模型为 `gpt-4.1-mini`，可用 `--model` 切换。模型调用发生在本机，密钥只读取自命令的环境变量。

```bash
npm run analyze -- --mode structured --output structured.json
npm run analyze -- --mode baseline --output baseline.json
node scripts/compare.mjs baseline.json structured.json
```

默认输入为公开反馈快照。自定义输入使用 `--input my-issues.json`，格式参照 `dist/data/issues.json`。每次接受最多 100 条反馈。分析前请确认有权限将所选数据发送给模型服务。生成的 JSON 可以通过网站右上角「导入反馈」查看与审核。

分步模式先逐条抽取组件、现象、触发条件与影响，然后按实际问题归并，最后根据原文起草主题、验证动作和逐字引用。单轮基线使用同一模型直接生成相同格式。代码会检查每条反馈是否恰好归入一个主题，以及引用是否存在于对应 Issue 的标题或摘录中。引用对应的语义支持仍由人工审核。已运行的比较为 TF-IDF 与 MiniLM，生成式两条路线提供可复现的调用与对比脚本。
